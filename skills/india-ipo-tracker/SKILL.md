# Indian IPO Tracker

## Shared evidence

Before collecting or interpreting inputs, read
[evidence and freshness](../india-research-core/references/evidence.md) and
[data access](../india-research-core/references/data-access.md). All sibling skills
are distributed with this suite. Load other procedures only when the task needs
them; apply them in the current session without assuming additional agents exist.

Read [IPO methods](../india-research-core/references/ipo-methods.md).

1. Set as-of and scope (mainboard/SME, upcoming/open/recently listed). Verify issue
   identity and status from exchanges/offer documents; distinguish rumored issues.
2. Build a dated calendar of offer open/close, pricing, allotment and listing
   events using official issue-specific updates. Preserve postponements,
   withdrawals, amendments and source revisions instead of erasing history.
3. Record subscriptions by category with denominators and time. Collect GMP by
   default for active issues using the same freshness/conflict/null rules as IPO
   analysis. Store each observation with source; never synthesize missing history.
4. Surface material changes since the previous snapshot, data gaps, pending
   catalysts and which issues merit `india-ipo-analysis`. A ranked list must state
   its criteria; GMP ranking is not a quality ranking.
5. For listed issues, compare actual issue/listing/current prices and dated returns,
   adjustment basis, liquidity and original thesis. GMP becomes historical.

Deliver calendar/table and changes. Store snapshots locally when requested.
Invoking a tracker performs one review; periodic jobs and notification destinations
must be separately configured and verified before claiming active monitoring.
