# Indian Research Journal

## Shared evidence

Before collecting or interpreting inputs, read
[evidence and freshness](../india-research-core/references/evidence.md) and
[data access](../india-research-core/references/data-access.md). All sibling skills
are distributed with this suite. Load other procedures only when the task needs
them; apply them in the current session without assuming additional agents exist.

1. Use the existing user-designated local research directory, or workspace-local
   `results/` by default. Apply
   [saving results](../india-research-core/references/saving-results.md) to completed
   reports without waiting for a separate save request. Keep
   issuer/security, report timestamp, sources/hashes, investment horizon, verdict,
   assumptions, entry plan, risks and review triggers together.
2. Use the [structured report contract](../india-research-core/references/report-contracts.md)
   for stock/IPO records. Preserve prior records; write a new dated revision rather
   than silently overwriting history. Do not put personal holdings in the package.
3. On review, compare original expectations with actual dated evidence and returns
   using proper corporate-action/dividend basis. Separate information unavailable
   then from evidence that was overlooked. Track thesis changes and why.
4. Record decision quality, forecast error, sizing/execution issues if supplied,
   and alternative explanations. A profitable outcome can follow poor reasoning;
   a loss does not alone falsify a sound process.
5. Recommend specific research/process changes supported by repeated evidence.
   A few outcomes do not establish calibrated skill or a new universal rule.

Deliver a dated thesis record, change log or postmortem. Saving research does not
create broker activity, notifications, persistent memory outside these files, or
background monitoring.
