# Indian Watchlist Review

## Shared evidence

Before collecting or interpreting inputs, read
[evidence and freshness](../india-research-core/references/evidence.md) and
[data access](../india-research-core/references/data-access.md). All sibling skills
are distributed with this suite. Load other procedures only when the task needs
them; apply them in the current session without assuming additional agents exist.

1. Resolve watchlist and the last known snapshot/cutoff. Without prior evidence,
   create a clearly labeled baseline rather than claim a change. Preserve names,
   thesis variables, desired entry zones and user-defined materiality thresholds.
2. Refresh relevant results, ownership/pledges, material announcements, news,
   corporate actions, price/valuation, sector/market context and upcoming catalysts.
   Use the same source/basis as prior records or reconcile a change.
3. Classify observations: thesis improving/deteriorating/unchanged/uncertain;
   entry condition reached or invalidated; pending catalyst; missing evidence.
   A sampled daily low does not prove a fill at a desired price.
4. Re-evaluate current-price attractiveness and timeframe for material changes
   using stock research and entry methods. Price-only alerts should not imply a
   full updated investment recommendation.
5. Deliver ranked changes, supporting links, unchanged key assumptions, required
   follow-up and next review events. Save the dated Markdown review under
   workspace-local `results/` by default; preserve prior snapshots.

This skill performs a review when invoked. Only configure periodic jobs or
external delivery on explicit instruction with a real scheduler/tool, and verify
its state before claiming monitoring or notifications are active.
